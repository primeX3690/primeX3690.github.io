Philosophy

Why zero-LLM, CPU-only autonomy.

Most "intelligent" systems today are wrappers around cloud LLMs — dependent on connectivity, GPUs, and API uptime. That breaks exactly where autonomy matters most: disaster zones, space, and disconnected edge environments with no guaranteed network or compute. Every system in this portfolio is built to run without any of that — interpretable, offline-capable, and deployable on constrained hardware. That's the bet: autonomy that keeps working when the cloud isn't there.

MOD-06 · RTL-EVOLUTION
🔧 EvoHDL — Genetic RTL Optimization
R&D
Problem
RTL optimization — writing Verilog, synthesizing it, then manually tweaking for area and timing — is still a manual process. Engineers run dozens of iterations by hand per chip, and it needs senior-level expertise that doesn't scale as design complexity grows.
Solution
EvoHDL evolves Verilog RTL automatically using genetic programming. A population of design variants improves generation over generation, using real EDA tools as the fitness function — Verilator for functional correctness, Yosys for area/timing — not a learned approximation. Every design is verified bit-exact correct before its area/delay even gets considered, so the system can never pick a smaller-but-wrong circuit.
Python 3.11VerilatorYosyspytestStreamlit
Key Metrics
  • 24.7% average area reduction (gate count) vs. hand-optimized RTL across 10 benchmark circuits
  • 18.3% improvement in critical path timing (frequency uplift) after 50 generations
  • 100% functional correctness guaranteed — Verilator validation passes for all synthesized designs before area/timing is even measured
  • Converges to optimal design within 75–100 generations (~12 minutes on a single CPU core)
  • Tested on 8-bit multipliers, ALUs, and FSM controllers — all designs pass formal linting and bit-exact simulation
  • Currently simulation-only using open-source EDA tools (Verilator + Yosys). Ready for ASIC/FPGA flow integration.
Verilog variants get bred generation over generation, but nothing survives on looks — Verilator has to confirm it's functionally correct before Yosys even gets to measure area and timing. A design that's smaller but wrong never makes it past that gate.

MOD-08 · SAFE-AUTONOMY
🛡️ SafeEvo — Safety-Gated Evolutionary Autonomy Stack
R&D
Problem
Robot autonomy today sits at two extremes — frozen, hand-tuned policies that break the moment the environment changes, or GPU-heavy RL that needs cloud compute a solo builder can't afford. Missing piece: a robot that improves from its own experience without a GPU budget.
Solution
A layered stack — classical, explainable components that should never fail (Kalman filter state estimation, A* planning, hard safety limits) plus a small evolving neural policy (~400 parameters) trained with a gradient-free Evolution Strategy — no backprop, no GPU. The safety layer can always override the learned policy's output, so the system stays predictable even while it's still learning.
PythonNumPy/SciPyExtended Kalman FilterA*ROS2MAVLink
Key Metrics
  • 43/43 automated tests passing
  • Safety layer cuts collision rate from 46.0% → 10.7% (~35pp drop)
  • Zero GPU used — ~2,600 simulation steps/sec on CPU
  • Evolutionary training: best fitness 58.90, 726.5 sim steps/sec, 0.194 gen/sec (~3.1 episodes/sec)
  • ROS2 / MAVLink interfaces built but not yet hardware-tested — simulation-only so far.
A Kalman filter and A* planner handle the parts that can never be allowed to fail, while a small evolving policy handles the parts that get better with practice. If the two ever disagree, the safety layer overrides the learned policy — not the other way around.
